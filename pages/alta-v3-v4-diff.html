04v3の知識のまま解くと間違えやすい点

境界値の選び方

v3
2値または3値の境界値分析。リスクが高ければ3値。
v4
ドメインテストのONポイントとOFFポイント。閉じた境界線（≤、≥、＝）か開いた境界線（＜、＞、≠）かで位置が変わる。「≠」はOFF1つとON2つ。

v4.0 3.1.1項

デシジョンテーブルのカバレッジ

v3
各ルールを1つのテストケースでカバーする。
v4
最小化とチェックサムが加わる。チェックサムが等しくても等価は保証されない。リスクが高い表は最小化を控え、完全な表でカバレッジを測る。

v4.0 3.3.1項

リスクアセスメントでのTAの役割

v3
TTAが可能性、TAがビジネスへの影響の把握に貢献する。テストの優先度付けは縦型探索・横型探索。
v4
役割の分担は書かれていない。TAが見積もる要素に「テストベースの品質」も含まれる。リスクコントロールでは、リグレッションテストの選択技法（影響度分析など）を使い分ける。

v4.0 2.1節、2.2節

品質モデルの名称

v3
ISO/IEC 25010:2011。使用性（UI快美性・アクセシビリティなど）、移植性（設置性・環境適応性・置換性）。
v4
ISO/IEC 25010:2023。使用性は「インタラクション容易性」、移植性は「柔軟性」に名称変更され、柔軟性に「拡張性」が追加された。

v4.0 第4章、付録F

柔軟性（移植性）テストの担当

v3
設置性・環境適応性・置換性のテストにTAが関わる。置換性テストは機能統合テストと並行してTAが実行できる。
v4
TAが焦点を当てるのは適応性とインストール性。拡張性はPT、置換性はTTAのシラバスで扱う。

v4.0 4.3節

レビュー

v3
チェックリストベースドレビューがTAの中心。要件用とユーザーストーリー用のチェックリストの項目を覚える。
v4
アドホック、チェックリストベースド、シナリオベースド、ロールベースド、パースペクティブベースドリーディングの5つを状況に応じて使い分ける。

v4.0 5.2.2項

ツールの種類

v3
テスト設計ツール、テストデータ準備ツール、テスト自動実行ツール。
v4
テストウェアのマネジメントの観点で、テストマネジメント、欠陥マネジメント、テストデータマネジメント、構成管理、要件マネジメントの各ツール。

v4.0 1.3.7項

欠陥分類（欠陥分類法）の使い道

v3
欠陥ベースのテスト技法として、欠陥のタイプの一覧からテストを導き出す。
v4
主に第5章で、欠陥を分類して種類ごとに根本原因分析（RCA）を行うために使う。ODC、IEEE 1044などが例。

v4.0 5.3.2項（チェックリスト作成の情報源としての記述は3.4.2項に残る）
